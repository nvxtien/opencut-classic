MCP server + Headless render cho OpenCut

Để agent (Claude, Codex…) dựng video bằng lệnh có cấu trúc thay vì click UI, và render ra file mà không cần mở trình duyệt.

Phát hiện chính, từ việc đọc code thật Phần nặng nhất của pipeline — GPU compositor (gpu / compositor / effects / masks) — đã headless-ready trên native. GpuContext::new() chỉ cần web_sys/canvas khi build cho wasm32; trên native nó dùng wgpu qua Metal, render-to-texture, không cần display. Ba lớp còn chặn headless thật sự — vẽ layer, decode media, audio — đều có giải pháp server-side đã kiểm chứng rộng rãi.

Agent gửi lệnh qua MCP → thao tác project store (data thuần) → export kích hoạt job render chạy ba lớp song song, không qua trình duyệt.

2.1 — Project store

TProject / TScene / TimelineTrack hiện đã là data thuần (không gắn DOM) → dùng thẳng làm schema. Chỉ cần viết Zod schema song song để validate input từ MCP tool, và bỏ các field chỉ dùng cho UI (timelineViewState, thumbnail dạng blob URL).

2.2 — Native render engine

Crate mới rust/crates/headless-render (hoặc N-API binding qua napi-rs) gọi thẳng gpu::GpuContext, compositor, effects, masks — không qua wasm-bindgen, build cho target native. Rủi ro thấp nhất vì code đã target-agnostic.

2.3 — Layer compositing

Dùng @napi-rs/canvas (Skia native, API tương thích OffscreenCanvas/CanvasRenderingContext2D) chạy trong Node — tái dùng phần lớn canvas-renderer.ts và nodes/*.ts gần như nguyên bản, thay vì viết lại bằng Rust. Lựa chọn thực dụng: ít rủi ro, tốc độ phát triển nhanh.

2.4 — Media I/O

Thay mediabunny/WebCodecs bằng ffmpeg (spawn process) — decode frame theo thời điểm cần, encode frame ra video output. Audio dùng filter graph ffmpeg (amix, atrim, volume) thay AudioContext/OfflineAudioContext — thay thế trực tiếp, không cần port logic DSP.

03

Phase 0 — rủi ro kiến trúc, đã spike xong

Chạy thật trên máy (Apple M1, macOS), 04/11/2026 — không phải suy đoán từ tài liệu. Code spike lưu tại docs/spikes/.

✓

wgpu init headless trên macOS — PASS

Binary Rust (docs/spikes/gpu-spike) gọi GpuContext::new() ngoài wasm, tạo render texture, clear màu, copy-to-buffer, đọc lại pixel. Kết quả thật:

adapter acquired: name=Apple M1 backend=Metal device_type=IntegratedGpu
texture_format=Bgra8Unorm first_pixel_bytes=[0, 0, 255, 255]
PASS: render-to-texture + readback round-trip, fully headless,
no window/canvas/display involved.

Xác nhận acquire_device() native dùng InstanceDescriptor::new_without_display_handle() + compatible_surface: None — đúng kỳ vọng, không cần surface/window nào.

✓

@napi-rs/canvas tương thích — PASS, 7/7

save/restore/translate/scale/rotate, globalCompositeOperation (multiply/screen/overlay/lighter), ctx.filter = "blur(4px)", roundRect, font + measureText (có actualBoundingBox) + fillText, và xuất PNG thật — mở ảnh thấy đúng rect bo góc + text render đúng font/vị trí. API bám sát Canvas2D chuẩn, phần lớn canvas-renderer.ts/nodes/*.ts tái dùng gần như nguyên bản, chỉ đổi điểm khởi tạo canvas.

~

Font loading — xác nhận một phần

GlobalFonts.registerFromPath() nạp được font .ttf hệ thống, ctx.font nhận đúng family. Chưa kiểm web font (Google Fonts tải về rồi register) — để lúc build thật.

~

ffmpeg decode — xác nhận bước đầu

ffmpeg -f lavfi ... -f rawvideo -pix_fmt rgba xuất đúng width×height×4 byte. Chưa kiểm frame timing cho retime/speed ramp, color space, audio resample — cần project thật để so sánh, để lúc build.

Kết luận: không còn rủi ro kiến trúc. Hai rủi ro lớn nhất (wgpu headless, napi-rs/canvas) đã pass với bằng chứng chạy thật. Phần còn lại là chi tiết tích hợp, xử lý trong lúc build Phase 1–4.

04

Lộ trình triển khai

Sau khi Phase 0 pass.

  1. Project schema + Zod validation — xong

    Package packages/project-schema: MediaTime/FrameRate mirror đúng struct Rust, đủ 7 loại element + 5 loại track, Mask/ElementAnimations passthrough có chủ đích (ngoài MVP). 7/7 test round-trip PASS, tsc --noEmit sạch.

  2. headless-render orchestrator — xong

    Package packages/headless-render. Phát hiện: với MVP (không effect/mask), native compositor crate Rust không nằm trên đường găng — base compositing trong code gốc là Canvas2D thuần, GPU chỉ phục vụ effect/mask. Nên pipeline MVP chỉ cần napi-rs/canvas + ffmpeg. Test end-to-end thật: render 15 frame từ project mẫu (1 clip + 1 text) → ffprobe xác nhận đúng codec/kích thước/số frame, xem 1 frame bằng mắt thấy đúng cả video lẫn text overlay.

  3. MCP server — xong

    Package packages/mcp-server, @modelcontextprotocol/sdk qua stdio, đủ 10 tool. Mọi tool nhận/trả thời gian bằng giây, quy đổi sang MediaTime tick ở biên. add_media dùng ffprobe thật, export_video không block (job nền + poll). Test 2 lớp — logic thuần (tools.test.ts) và giao thức MCP thật qua stdio process con + SDK Client thật (protocol.test.ts: tools/list đủ 10 tool, tools/call thành công lẫn báo lỗi đúng) — đều PASS.

  4. Test end-to-end — xong (qua MCP tool)

    Flow đầy đủ qua tool: create_project → add_media → add_clip → split_clip → trim_clip → add_text → export_video → poll đến "done" → ffprobe xác nhận file mp4 thật. Phần so sánh với bản export từ web gốc — ngoài phạm vi đã làm, cần build bản web chạy được để đối chiếu.

  5. Project persistence — xong

    Phát sinh từ lúc dùng thử thật (project mất khi server restart). Thiết kế: mỗi project → 1 file JSON riêng (~/.opencut-headless/projects/<id>.json, đổi được qua env). Lazy-load — không đọc gì lúc khởi động, chỉ đọc khi tool cần đúng project đó, nên khởi động nhanh bất kể có bao nhiêu project trên đĩa. Mỗi lần sửa ghi đè file ngay (write-through). Thêm tool list_projects + delete_project. media/jobs vẫn chỉ in-memory, cố ý, ghi rõ trong code. Test mô phỏng restart thật: ProjectStore thứ hai cùng thư mục, cache rỗng, đọc lại + list + export + xoá đều đúng — không đụng thư mục home thật.

05

Ngoài phạm vi MVP

Ghi nhận, chưa làm trong bản đầu.

  • Auto-caption/transcription — module transcription/ gọi model ASR cần xác minh riêng; có thể chạy server-side dễ dàng vì không DOM-bound, nhưng chưa khảo sát.
  • Sticker/graphic nâng cao, effect phức tạp, GPU-only effect preview.
  • Thiết kế ngược (round-trip) — mở lại project JSON trong UI web để người dùng sửa tay sau khi agent tạo. Cần, nhưng không chặn MVP.
