MCP là gì?

Phần nền tảng — để phần còn lại của trang dễ hiểu hơn.

MCP (Model Context Protocol) là một giao thức mở do Anthropic phát triển (2024), chuẩn hoá cách một AI agent (Claude, hay agent khác) kết nối với công cụ và dữ liệu bên ngoài. Ví von hay dùng: MCP giống USB-C cho AI — thay vì mỗi tool phải viết một kiểu tích hợp riêng cho từng app AI, viết một MCP server một lần là dùng được với mọi client hỗ trợ MCP (Claude Desktop, Claude Code, Cursor...).

Kiến trúc 3 thành phần

Host
App chứa AI mà người dùng tương tác trực tiếp — ví dụ Claude Desktop. Quản lý vòng đời của các Client, hiển thị UI xin phép (trust/approve) khi kết nối server mới.
Client
Sống bên trong Host, giữ 1 kết nối 1-1 với đúng 1 Server. Dịch lệnh model muốn gọi thành JSON-RPC request, nhận kết quả trả về cho model.
Server
Tiến trình riêng (như packages/mcp-server trong dự án này) — expose Tools (hành động có side-effect, vd export_video), Resources (dữ liệu đọc, vd nội dung file), Prompts (mẫu câu lệnh dựng sẵn). Không biết gì về cách model suy luận — chỉ trả lời đúng request.

Giao thức bên dưới: JSON-RPC 2.0, qua 1 trong 2 kiểu transport — stdio (server là tiến trình con, giao tiếp qua stdin/stdout, chỉ chạy local) hoặc HTTP (server là web service, nhận POST). Bắt tay ban đầu: initialize → notifications/initialized → model gọi tools/list để biết có tool gì, rồi tools/call để thực thi — đúng những gì protocol.test.ts trong dự án này kiểm thử.

Lợi ích

  • Viết một lần, dùng nhiều nơi — server này (opencut-headless) hoạt động với Claude Desktop, Claude Code CLI, hay bất kỳ client MCP nào khác, không cần code riêng cho từng app.
  • Schema rõ ràng, an toàn hơn "code tự do" — mỗi tool khai báo input schema (Zod → JSON Schema), agent chỉ gọi được qua interface đã định nghĩa, không chạy lệnh tuỳ ý.
  • Tách biệt rõ trách nhiệm — logic nghiệp vụ (tools.ts) hoàn toàn độc lập với lớp giao thức (register-tools.ts), nên test được logic mà không cần dựng transport (đúng pattern 2 lớp test đã dùng xuyên suốt dự án này).
  • Composable — một agent nối nhiều MCP server cùng lúc (trong session thật đang dùng: opencut-headless cùng với Google Docs, GitHub, Slack...), phối hợp tool từ nhiều nguồn trong một tác vụ.

Hạn chế

  • Thêm một lớp gián tiếp — mọi lệnh đi qua JSON-RPC thay vì gọi hàm trực tiếp, tốn thêm độ trễ (nhỏ, nhưng không phải 0).
  • Không có auth chuẩn cho stdio — ai chạy được lệnh trên máy là dùng được server, không có lớp xác thực mặc định (HTTP transport có OAuth, nhưng phức tạp hơn để tự host).
  • UX trust/approval còn non — đúng như saga gặp phải: quyết định reject một server bị lưu ngầm, không có cảnh báo rõ ràng; cấu hình không hot-reload giữa session đang chạy.
  • Không phải client nào cũng hỗ trợ như nhau — có client chỉ nhận stdio, có client (như "Add custom connector" trong app GUI) chỉ nhận HTTP(S) public, không nhận local — phải tự cân nhắc transport nào phù hợp nơi sẽ dùng.
  • Tác vụ dài chưa có cơ chế chuẩn mạnh — streaming tiến độ không chuẩn hoá tốt, nên dự án này phải tự làm job nền + tool polling riêng (export_video trả jobId, get_render_status để hỏi lại) thay vì có sẵn pattern "long-running tool" trong giao thức.

Xuất phát điểm

Trước khi code dòng nào, đã khảo sát các lựa chọn có sẵn để trả lời "ai đã làm việc này rồi".

Shotstack / Creatomate / JSON2Video
Có MCP + headless thật, nhưng là engine "tạo video theo template" (ads, social clip) — không phải editor cắt dựng đầy đủ tính năng như CapCut.
Remotion
Video = code (React), headless render mạnh — nhưng MCP server chính thức của họ đã bị tắt (26/10/2026), chuyển sang Agent Skills.
DaVinci Resolve + MCP
Editor full tính năng, có MCP server cộng đồng (~440 tool) — nhưng cần bản Studio trả phí cho nhiều tính năng, và không chạy headless thuần (vẫn cần app GUI mở).
OpenCut-classic
Mã nguồn mở (MIT), kiến trúc tách UI khỏi logic rõ ràng, action registry có sẵn — nhưng archived, không có API. Chọn fork và tự thêm MCP + headless lên trên.

4 phase, mỗi phase xác thực bằng chạy thật

Không có phase nào dừng ở "nên hoạt động" — mỗi bước đều có bằng chứng chạy được trên máy.

PHASE 0

Spike rủi ro kiến trúc

PASS

Trước khi cam kết hướng "server-side thuần", xác thực 2 rủi ro lớn nhất bằng code chạy thật, không suy đoán.

Binary Rust gọi GpuContext::new() ngoài wasm — chạy headless trên Metal (Apple M1), không cần canvas/display. @napi-rs/canvas — 7/7 API check PASS (blend mode, filter, text, xuất PNG thật).
PHASE 1

Project schema

PASS

Package project-schema — Zod schema mirror đúng cấu trúc TProject/timeline gốc, MediaTime/FrameRate khớp struct Rust.

7/7 test round-trip: parse hợp lệ, reject dữ liệu sai (MediaTime phân số, fps denominator=0...), passthrough có chủ đích cho Mask/Animation ngoài MVP.
PHASE 2

Headless render

PASS

Phát hiện quan trọng: với scope MVP (không effect/mask), compositor GPU Rust không cần thiết — napi-rs/canvas + ffmpeg đủ để render.

Render 15 frame từ project mẫu (1 clip + 1 text) → ffprobe xác nhận đúng codec/kích thước/số frame. Frame trích ra xem bằng mắt khớp.
PHASE 3

MCP server

PASS

10 tool ban đầu, qua @modelcontextprotocol/sdk, cả stdio lẫn HTTP transport.

Test 2 lớp: logic thuần + spawn server thật qua stdio/HTTP, dùng MCP Client thật gọi tools/list/tools/call qua wire protocol — không chỉ gọi hàm nội bộ.
PHASE 4

Persistence

PASS

Phát sinh từ lúc dùng thử thật — project mất khi restart. Thêm lazy-load + write-through, 1 file JSON/project, tool list_projects + delete_project (12 tool).

Test mô phỏng restart thật: ProjectStore thứ hai, cache rỗng, đọc lại + export + xoá đều đúng.

Hành trình kết nối — khó hơn cả việc build server

Server chạy đúng ngay từ đầu. Khó nhất hoá ra là nối nó vào app Claude Desktop thật.

1
Terminal không thấy 10 tool — session chat đã mở trước khi .mcp.json tồn tại. Bài học: MCP config chỉ đọc lúc session khởi động, không hot-reload.
2
Màn hình "Add custom connector" của app GUI chỉ nhận HTTPS URL, không nhận lệnh local (stdio) — phải thêm hẳn một HTTP transport mới cho server để thử đường này.
3
localhost không bao giờ hoạt động với connector đó — app GUI kết nối từ server Anthropic trên cloud, không phải từ máy local. Cần tunnel public + auth mới dùng được → chọn quay lại CLI stdio, an toàn hơn.
4
CLI thật vẫn không thấy server dù .mcp.json đúng — debug bằng claude mcp get, phát hiện status "✘ Rejected": một lần approve/reject trước đó đã bị lưu lại. Fix bằng claude mcp reset-project-choices.
5
Thành công — 12 tool xuất hiện, gọi thật qua create_project → add_media → add_clip → add_text → export_video, video mp4 720p render ra đúng, frame xem bằng mắt khớp timecode.

Giới hạn đã biết, ghi lại không giấu

  • Chưa có audio trong export, chưa letterbox/crop tỉ lệ khung hình (scale méo).
  • Decode ffmpeg 1 process/frame — đúng nhưng chậm với clip dài.
  • media và render job vẫn chỉ in-memory — mất khi server restart (chỉ project được lưu ra đĩa).
  • Không có file lock — hai client cùng ghi một project cùng lúc có thể đè dữ liệu nhau.
  • Chưa so sánh pixel-for-pixel với bản export từ web gốc (opencut-classic chưa build được bản web để đối chiếu).
